# RECON-2.0.0 — patches

**Status:** Informative. Defects and gaps found in `RECON-2.0.0.md` after it was written (second read, 2026-11-04). Each item is applied in the draft ledger (`SPEC-2.0.0-draft.md`) and cross-referenced there. Items marked **owner decision** need a verdict before the freeze.

| ID | Finding | Patch | Where applied |
|---|---|---|---|
| RP-1 | RECON §6 content plan omits **DoD-1** and **M5**. D-27 re-cuts the headline to the uncovered-outside mask but DoD-1 in 1.2.0 still names `IoU(PARKED)` as a floor, and M5 acceptance still cites `IoU(PARKED)`. An un-patched DoD-1 would leave the money floor pointing at the label the RECON just stopped measuring. | DoD-1 and M5 acceptance floors re-referenced to the two masks. | L-02, L-25 |
| RP-2 | **Pilot deadlock.** Kill-gates (§8) require M4 tier agreement and `chartable` yield from a 5-race pilot, but G-1…G-3 block M4 until M1–M3 pass acceptance on golden data, and golden charting is forbidden before the freeze that the kill-gates gate. Circular. | Pilot runs on a throwaway stack explicitly exempt from G-1…G-3; outputs are freeze evidence only, tagged `producer_kind = pilot_throwaway`, never corpus artifacts. | L-07, L-40; `protocols/PILOT-5/` |
| RP-3 | S-1 renames `first_over` but RECON forgets the sibling `first_over_ambiguous` (§2.3, §9 payload constraints). | Rename both: `lead_uncovered_outside`, `lead_uncovered_outside_ambiguous`. | L-12, L-37 |
| RP-4 | §6.4 operating characteristic: at per-sample accuracy 0.95, P(≥ 35 of 36 correct) = 0.95^36 + 36·0.95^35·0.05 ≈ **0.459**, not 0.44. (At 0.99: ≈ 0.947. At 0.98: ≈ 0.835.) Under non-independence the true numbers are worse, which is the point of the stratified resampling. | Value corrected to ≈ 0.46. | L-33 |
| RP-5 | **Lateral scale is predicted to be wrong, not measured** (owner decision). SW := SL × `sw_ratio` assumes lateral screen distance scales like longitudinal. The wide pan is oblique: with camera yaw θ to the pack axis, a lateral separation of one lane projects to ≈ sin θ of its longitudinal equivalent (≈ 0.34 at 20°). `same_tier_sw = 0.6` could then merge adjacent lanes, and a parked horse one lane out could read as covered under `cover_lat_sw = 0.8`. Bends add a second error: a straight principal axis fitted to a ~40 m pack on a ~115 m-radius bend puts ~1 SW of false lateral spread on the tail. | Added to OD-1x step 4: measure lateral gaps between known-adjacent runners on the near straight, far straight and a bend; report the ratio of apparent lateral lane width to SL per location. If the ratio varies by more than 2× across locations, `sw_ratio` becomes per-shot-calibrated (new key `sw_ratio_method`), and this is an additional MAJOR justification. | L-45; `protocols/OD-1x/PROTOCOL.md` step 4 |
| RP-6 | **Official tracking may exist.** LeTrot has published pages on "la technologie Tracking sur les courses de Vincennes" and integrating tracking data on letrot.com. Only titles were seen. If per-runner positional data (even sectional/rank) is published, it could replace M2–M4 for position/rank and leave CV for cover/tier only, or replace the project. | Register entry; owner reads the two pages before P4. Outcome recorded in `STATUS.md`. | L-44 |
| RP-7 | **No signal gate.** Every kill-gate tests feasibility; none tests whether trip data adds edge over the market. The spec explicitly scopes prediction out, but a feasibility-only project can succeed at building something with no value. | New protocol `protocols/SIGNAL-GATE/`: test attested notule trip phrases from prior races against closing odds / results on the owner's existing corpus. Cheap because it uses text, not video. Result is a go/no-go input to P4, not a spec change. | `protocols/SIGNAL-GATE/PROTOCOL.md` |
| RP-8 | `rail_side` heuristic ("lower on-screen tier-1 line") is stated once for "the Vincennes wide pan". Vincennes races the corde on the left; seen from the stands, the lower-on-screen line is the rail on only one straight. | OD-1x step 4 records which side the rail is on-screen for each location. Heuristic becomes per-shot and is already human-confirmed on low confidence (§3.1), so no structural change; the default proposal must not be wrong most of the time. | `protocols/OD-1x/PROTOCOL.md` step 4 |
| RP-9 | RECON §1 table rows for F-1 and §1.3 are broken by unescaped `|` inside inline math (`|w_X − w_Y|`, `~p95 of |…|`). Rendered table loses the Decision/Gate columns for those rows. | Written with escaped pipes in the ledger. | L-11, registry |
| RP-10 | `anchor_duration_tolerance_s` is not explicitly retired in RECON §6 §7.1 list. | Removed in TS-0.0.0-provisional; replaced by the four per-start-type keys. | L-34 |
| RP-11 | **D-26 opens a classification-table gap** (owner decision). Cover is now tier-independent, so a tier-1 runner with no tier-1 runner ahead (the 1.2.0 `LEADER`) can be covered by a tier-2 runner slightly ahead within `cover_lat_sw`. §2.3 has no row for "tier 1, rank 1 in tier, covered". Found by the reference implementation (`tripstate.m5_states.classify`). | Options: (a) `LEADER` keeps precedence and records `covered = true` (leader-by-rail with outside cover is a real position); (b) new state. Until decided, the code emits `UNKNOWN` + reason `table_gap_tier1_lead_covered`, per prime directive. Recommendation: (a). | L-12; `src/tripstate/m5_states/README.md` |
